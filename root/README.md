# root/ – zeus-root (not installed yet)

zeus-root is the small root-side part of Zeus's **root actions** (`docs/design.md` §16, `docs/contract.md` §8): a short, fixed list of scripts that need root (closing a port, restarting a system service), each one run only after the owner touched a passkey on {{PHONE}}.

- `zeus_root/` is the runner and its command line. It is **not** part of the `zeus` package and never imports it. On {{SERVER}} it runs as `/usr/bin/python3 -I` from root-owned files, with the standard library and `cryptography` only. Every path, account, clock and outside command goes through one `Ctx` (`zeus_root/ctx.py`): `Ctx.system()` uses constants only, and tests build their own on temporary folders.
- `canon.py` holds the pure checks: canonical JSON (ASCII only, shared with the key page, not with `zeus/log.py`), strict parsing, base64url, the challenge, key refs and run ids.
- `state.py` is root's own state under `/var/lib/zeus-root` (nonces, counters, the pause, refusal counts, the hourly attention windows, limits, the lock); `logs.py` the run log with its hash chain, the result files and the attention lines; `config.py` the config, the fixed list, the keys, owners and labels, and the file rules; `take.py` the hostile take of the inbox and the quarantine.
- `webauthn.py` verifies the phone's assertion for one record, in the order of `docs/design.md` §16.4 step 6 (the signature, then freshness and the spent nonce, all before the counter and BE flag). Marking the nonce used, through the `spend` the runner passes in, is its one side effect: once for every record that reaches it with a nonce of the right shape, whatever the answer, and kept a day, or, once its signature checked out, until a day after the record's signed `exp` (`state.spend_nonce`), so a record root refused can never run later when it is sent again as it was; a record with an `exp` more than a day ahead that root first saw spoiled is the key page's to stop (contract §8b, "Every answer spends the nonce"). Its tests use the W3C WebAuthn Level 3 test vectors (`tests/root_fixtures/w3c-l3-vectors.json`, notice in `W3C-NOTICE.md`) and two assertions from a Chromium virtual authenticator, made once by `tests/root_fixtures/make_chromium_fixtures.mjs` and committed.

**Nothing here is installed or running.** The slices build it in order: Z2 the runner and the command line, Z3 the gate and the units, Z4 the key page, Z5 the installer. Code under `root/` never merges by itself: each slice gets a fresh-context hostile review and the owner's yes in the chat (`CLAUDE.md`).

Tests: `bash tests/run.sh root_canon` (and the other `root_*` tests). A test that needs Linux or `cryptography` skips elsewhere, except in CI, where `ZEUS_ROOT_TESTS_REQUIRED=1` turns a skip into a failure.
